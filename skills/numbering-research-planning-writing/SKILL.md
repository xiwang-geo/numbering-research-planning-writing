# Numbering Research Planning Writing / 编号研究规划撰写

Write the numbered research-execution plan this researcher uses each round: a
document that narrows an advisor's direction to ONE testable question, proves the
question is not already published, and breaks the round into numbered task blocks
whose completion is mechanically checkable.

编号研究规划撰写。产出的是**本轮要逐步执行并汇报的研究执行计划**，不是头脑风暴、
不是假设清单、也不是周报——周报是另一份交付物，有自己的固定格式。

## When to Use / 何时使用

- 「写一个详细的研究规划」「写一个研究规划」「出一个详细的规划」「路线X的详细研究规划」
- 「这周的研究计划」「下周的计划」——导师反馈到了，需要先把本轮范围写定再动手
- 需要做路线决定：继续 / 收窄 / 停止
- 上一轮规划需要修订（v2）：定义或数据来源被纠正之后

**Don't use for:** the weekly `.docx` progress report, a literature review, one
paper's methods section, or a software implementation plan.

## The house format / 固定格式

Section order is load-bearing: each section constrains the next one.

```
# <轮次> 研究规划 <收窄后的问题>

制定日期：<YYYY-MM-DD>。执行窗口：<start> 至 <end>，可按资料到达情况顺延。

<一句话：这一轮相对上一轮变了什么、这一轮检验什么。若定义或数据来源被纠正，
在此说明 v2 改动。>

按用户要求，本轮新增资料、代码、结果和核验都保存在 `<round-dir>/`。旧原件及
冻结分析保留在原处，以来源路径和哈希引用，不搬动、不覆盖。

## 一 我对<导师/来源>建议的理解
## 二 <核心术语> 具体指什么
## 三 先核创新空间 不把<方法/分类>本身当创新
## 四 本周逐项执行任务
## 五 两轮核验
## 六 阶段决定
```

### 一、我对导师建议的理解

**这一节是全部工作发生的地方。** 导师的反馈是方向，不是问题。把它收窄成一句
本轮能回答、且用已有或已在下载的资料能回答的小问题。

- 一句话写出问题，并让**比较对象显式**（"在相近季节、雨量和OLR背景下，云的类型
  组成不同，是否仍对应雨水δ¹⁸O差异？"）。
- 写清**上一轮已经建立了什么、没有建立什么**。新问题必须落在旧结果的空缺里，
  不是把旧结果换个说法重讲。
- 导师给了好几条建议时，**不会全部变成模型变量**。说清这轮取哪一条、其余为何搁置。
- 越滚越大的路线是这个环节要防的失败模式。如果本轮仍横跨多个机制，继续收窄。

### 二、核心术语具体指什么

读者要能判断这份规划，必须先知道**中心量指什么、不能代表什么**。一节就够：

- 它指什么（定义来源给出链接）。
- **它不指什么**——至少一行。列出读者可能做的、且会改变结论的替换。
- 若术语是某个产品或分类：写清限制它的边界条件，以及不能从中推断出什么。

防术语偷换是这一节存在的理由。「光学厚度不是云有多厚」「水汽辐合不是空气辐合」
「再分析变量不是直接过程观测」。

### 三、先核创新空间

最近邻研究表，一篇一行：

| 最近研究 | 已有内容 | 我们要避开的重复 | 本轮需要补核 |
|---|---|---|---|
| <作者 年, 期刊, DOI> | <他们做了什么> | <我们不能重做的> | <我们必须读/核的> |

- 每行给出 DOI 或本地阅读报告的入口。
- 候选贡献**只写一句**，且必须**有条件**：能否发表取决于文献核读、资料支持、
  效应幅度与稳定性，不能提前保证。
- 「把方法X用到新区域」不是贡献。**删掉新区域后这句话若依然成立，它就不是贡献。**

### 四、逐项执行任务

每个任务块带**四个必备要素**，缺任何一个任务就不可证伪：

| 要素 | 要求 |
|---|---|
| **要回答** | 这一步解决的具体问题，或它补上的空缺 |
| **做什么** | 具体的操作，按顺序列出，并写明每步之前的前置检查 |
| **产出** | 这一步产出的文件，**带路径**——没有指名产物的任务不是任务 |
| **完成标准** | 别人可以核查的完成条件，**不是"结果得到确认"** |

可选项：`目的`（这一步为何存在）、`已知锚点`（这一步的起始样本数与站点锚点）、
`预期耗时`。

**任务编号在轮次之间稳定，永不为不同任务复用**：`R2-C01`、`WB01`、`BC01`、
`PB-01`、`TK-01`——路线字母 + 阶段字母 + 序号。沿用项目已有的编码体系；
一轮把编号全部重排，会让此前所有引用无法解析。

一轮正常是**六到十二个编号任务**。超过十二个那是路线不是一轮——拆开，并写明
本轮执行其中哪部分。

**冻结必须发生在数字出现之前。** 锚点计数是锚点，不是样本量：不同轮次的面板
不能相加当独立样本，锚点也不是新共同集的保证数量。训练/测试或时间截止日在拟合
**之前**写进任务块；因为拟合不好而移动截止日就是对着划分拟合。比较方式、模型集、
评分规则同样先定。

### 五、两轮核验

每轮以一份核验记录收尾，**两轮检查的不是同一件事**：

- **第一轮——机械。** 公式、原件、记录ID（UID）、单位、计算本身。从冻结输入独立重算。
- **第二轮——身份。** 图件、文字、分析身份、结论。文字是否仍在描述代码算出的东西？
  每张图是否都来自本轮脚本？

两轮写进同一个文件。**把同一份材料读一遍然后称作两轮，不算核验。**

门禁：两轮都过，这一轮才算完成。「不显著」是合法的完成结果——**完成标准
永远不能要求一个显著或有利的结果**。

### 六、图件逐图讲解

本轮产出的每张图都要有讲解：它**解释了什么**、它**不能解释什么**（边界条件、
样本稀疏度、哪个机制这张图区分不了）、以及视觉元素（坐标轴、图例条目、色标含义）。
只有标题数字而没有逐图讲解，不算完成的交付。

### 七、阶段决定

规划的最后一步是**决定**，三种永远可选：

- **继续**——下一项检验值得做，并指名是哪一项；
- **停止 / 收窄**——这条路不划算，说明原因；
- **换路**——另一条路线证据更充分，把证据摆出来。

决定不是「显著」也不是「不显著」，而是**下一份证据值不值得收集**。

## 目录约定

一轮产出放在一个轮次目录下，规划在前、决定在后：

```
<round-dir>/
  00_研究规划/          规划本体（+定义/下载说明附件）
  01_问题与资料/        来源索引、UID表、问题登记
  02_.../               每个任务领域一个目录，以任务命名
  03_核验/              两轮核验记录
  08_阶段决定/          阶段决定及其证据
```

每个子目录放一个 `README.md`，列出其中文件及一句话用途，使这一轮不打开任何文件
也能读懂。

## Pitfalls / 常见错误

- **绝不把计划写成已完成。** 未执行的一律用将来时，并标明是计划。
- **绝不让完成标准要求有利结果。**「关系得到确认」不是完成标准；
  「按训练期估计、在留出期评分，结果不论符号都已记录」才是。
- **不因为拟合不好就移动冻结的截止日。** 那是对着划分拟合，会毁掉划分的唯一作用。
- **不靠扫描所有类别、子集或参数**来找到显著结果并把它当主问题。主问题失败，
  就报告它失败了。
- **不把不同轮次的锚点相加**来宣称更大样本。
- **不把上一轮的数字直接搬过来**而不从磁盘文件重新推导——规划里写一个过期计数
  当锚点，会把错误传播到下游每一个任务。
- **定义被纠正时，不让它悄悄改变任务清单。** v2 要写明哪些任务因此改变、为什么，
  并把上一版留在 `版本记录/` 里。
- **不把规划写得密到别人无法执行。** 完成标准就是这件事的检验。

## Verification / 交付前检查

写完后运行随附的检查脚本，它按结构核对任务块契约：

```bash
python "${CLAUDE_SKILL_DIR}/scripts/check_plan.py" <plan.md>
```

脚本逐条检查每个任务块是否有四个必备要素、产出是否指名了文件、完成标准是否可
核查、编号是否重复，以及规划是否以两轮核验和阶段决定收尾。**有发现就修，改完
再跑，直到通过。** 脚本检查结构，不判断科学是否正确——后者由人负责。

再逐项人工核对：

- [ ] 本轮问题是一句话，并写明上一轮**没有**建立什么。
- [ ] 核心术语有定义，且至少一行「这不是那个」。
- [ ] 创新空间表存在，每行有 DOI 或阅读报告，候选贡献是有条件的。
- [ ] 每个任务块有 要回答 / 做什么 / 产出 / 完成标准，每个产出都指名了路径。
- [ ] 任务编号沿用项目既有体系，且未被复用。
- [ ] 锚点被标为锚点；划分在出结果之前就冻结。
- [ ] 两轮核验记录存在，两轮检查不同的东西，且都不要求有利结果。
- [ ] 每张图都有讲解，覆盖它不能解释什么。
- [ ] 阶段决定已记录，并附证据。
- [ ] 规划文件读回核对过上面这份清单。
